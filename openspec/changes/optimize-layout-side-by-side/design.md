## Context

Game Weaver 当前页面（`app/page.tsx`）使用 Tailwind CSS grid 实现上下堆叠布局。主容器使用 `grid-rows-[auto_minmax(860px,1fr)]` 将页面分为上半区（操作）和下半区（预览）。在桌面端（`lg:`），上半区约 42vh，下半区最小 1040px。这导致预览区需要大量滚动才能看到。

本次设计将页面重构为左右分栏布局，参考 Bolt.new、v0.dev、Replit 等 AI 工具的交互模式。技术栈不变：React + Tailwind CSS v4 + Next.js。

## Goals / Non-Goals

**Goals:**
- 桌面端（≥1024px）采用左右分栏布局，操作区和预览区同时可见
- 左侧面板独立滚动，右侧预览区固定
- 所有现有功能保持不变（生成策划、生成游戏、微调、等待小游戏、语音合成、视频生成）
- 保持亮色主题兼容
- 窄屏（<1024px）回退到垂直堆叠布局

**Non-Goals:**
- 不引入拖拽调整面板大小的功能（resizable panels）
- 不修改后端 API 或 AI 生成逻辑
- 不修改亮色主题的颜色规范（但会在规范内优化配色细节）
- 不新增暗色模式支持
- 不改变等待小游戏的内部逻辑
- 不引入额外的 UI 组件库或设计系统依赖

## Decisions

### Decision 1: 使用 CSS Grid `grid-template-columns` 实现左右分栏

**选择**：使用 Tailwind 的 responsive grid（`lg:grid-cols-[minmax(0,1fr)_minmax(0,1fr)]`）替代当前的 `grid-rows` 方案。

**替代方案**：
- **Flexbox 方案**（`flex-row`）：更简单，但 flex 在高度控制上不如 grid 精确，尤其是需要右侧面板撑满视口高度时。
- **CSS `position: fixed` 右侧面板**：可以实现固定预览，但会脱离正常文档流，在响应式和 z-index 管理上更复杂。

**理由**：Grid 可以同时精确控制列宽和行高，`h-[calc(100vh-65px)]` 确保右侧面板撑满视口。且 Tailwind 对 grid 的支持最为完善。

### Decision 2: 左侧面板使用 `overflow-y-auto` 独立滚动

**选择**：在左侧面板容器上设置 `overflow-y-auto`，配合 `max-h-[calc(100vh-65px)]` 或继承父级高度约束。

**理由**：这是实现独立滚动的最简单方式，无需引入额外的滚动库。Tailwind 原生支持。

### Decision 3: 列比例采用 5:5 或 4:6

**选择**：默认采用 `grid-cols-2`（50:50），待实现后根据内容密度微调。左列操作面板内容较多时可调整为 `lg:grid-cols-[45%_55%]`。

**替代方案**：
- 固定左侧宽度（如 480px）：适合操作区内容量固定的场景，但可能在不同屏幕尺寸下不够灵活。
- 三栏布局（输入 | 策划 | 预览）：更细分但增加了复杂度，且会让每个区域过窄。

**理由**：50:50 是最中性、最通用的起点，实现后可以快速调整。

### Decision 4: 等待小游戏（Mini-game）适配右侧面板

**选择**：小游戏的 canvas 和 UI 按比例缩放以适应右侧面板宽度，设置 `max-w-full` 让 canvas 自动适配。

**理由**：canvas 的 `width`/`height` 属性固定为 800×500，但通过 CSS `max-w-full` 可以缩放渲染。右侧面板宽度在 1024px 视口下约为 480-512px，800px 宽的 canvas 需要缩放到约 60%，仍可清晰显示。

### Decision 5: 微调输入栏移至左侧面板底部

**选择**：将微调输入框和按钮从预览区底部移至左侧操作面板的底部。

**理由**：微调是"操作"而非"预览"的一部分，放在左侧更符合逻辑分组。用户在编辑策划内容后自然会向下滚动找到微调区域。

### Decision 6: 去 AI 化的视觉风格

**选择**：采用克制、专业的视觉风格，参考 Linear、Vercel、Figma 等设计工具。具体措施：
- 字体层级：标题使用 `tracking-tight` 收紧字间距，正文保持默认间距。字号对比清晰（标题 15-18px vs 正文 12-13px）
- 阴影克制：所有阴影使用 `shadow-sm` 或 `shadow-[0_1px_2px_rgba(0,0,0,0.04)]` 级别，不用 `shadow-lg` 及以上
- 圆角一致：全部使用 `rounded-md`（6px）或 `rounded-lg`（8px），避免 `rounded-xl` 及以上的过度圆角
- 彩色克制：彩色仅用于主操作按钮（蓝/绿/琥珀），其余全部使用 zinc 中性色
- 空状态去 emoji 化：空状态使用简洁的文字 + 图标（Heroicon 级别的小 SVG），而非大号 emoji
- 过渡动画：所有 hover/focus 使用 `transition` + 150-200ms 的隐式 easing，不用 `animate-pulse` 等夸张动画
- 分隔线克制：多用留白分隔、少用显式 border，必需的分隔线使用 `border-zinc-100/200`

**替代方案**：
- 使用 shadcn/ui 或 Radix 组件库 → 引入额外依赖，与纯 Tailwind 项目不匹配
- 保留现有样式仅改布局 → 现有样式仍带有 AI 生成痕迹（emoji 图标、大圆角按钮、阴影过重）

**理由**：好的设计工具的界面应该"退后一步"，让用户专注于创作内容。克制的视觉语言让工具感觉可靠、专业，而非玩具化。

### Decision 7: 策划卡片的紧凑重设计

**选择**：将 6 个策划卡片从当前的大卡片（min-h-82px + 图标 + 标题 + 预览文本）改为紧凑行式列表或小标签式卡片（约 48-56px 高），点击后在下方展开编辑器。在左侧面板中放置一个可折叠的 tab 栏，每项只显示 icon + short label + 完成状态指示。

**理由**：左侧面板宽度有限（约 380-480px），当前卡片设计占用过多垂直空间。紧凑设计让用户无需滚动即可看到所有 6 个板块的状态，同时点击展开编辑的交互也更加聚焦。

## Risks / Trade-offs

- **[Risk]** 等待小游戏在较窄的右面板中可能显示过小 → **Mitigation**: canvas CSS 缩放 + 设置合理的最小列宽（`min-w-[480px]`）
- **[Risk]** 左侧面板内容多时需要大量滚动 → **Mitigation**: 策划卡片使用紧凑模式，编辑器 textarea 自适应高度
- **[Risk]** 窄屏回退到堆叠布局后，用户体验回到当前状态 → **Mitigation**: 这是可接受的折中，因为窄屏设备本身就不适合分栏
- **[Trade-off]** 左侧面板内容减少时右侧有大量留白 → 预览区居中显示占位符，保持视觉平衡
- **[Risk]** 去 AI 化后界面可能显得过于素净（"太简单"）→ **Mitigation**: 通过精致的微交互（hover 态颜色渐变、focus ring 渐变）和 precise spacing 补偿视觉丰富度，参考 Linear 的"less is more"哲学
- **[Trade-off]** 紧凑卡片可能降低策划内容的可预览性 → 在卡片上保留标题+完成指示器，通过 tooltip 或 hover 展开预览第一句话，点击后完整展示编辑器
